# Эрхийн загвар

> Phase 0. `ERD.md`-тай хамт уншина.

## Гурван зарчим

**1. Эрхийг зөвхөн сервер шийднэ.** Клиентээс ирсэн дүр, `user_id`, `school_id`
хэзээ ч итгэл хүлээхгүй. Дүрийг сесснээс, сесс нь серверээс.

**2. Бүх асуулга сургуулиар шүүгдэнэ.** `school_id` нь нэмэлт нөхцөл биш,
**заавал** нөхцөл. Үүнийг мартсан нэг асуулга нь бүх сургуулийн өгөгдлийг
нээнэ.

**3. Хандалт нь холбоосоор тодорхойлогдоно, дүрээр биш.** «Багш учраас харна»
биш — «энэ ангийн багш учраас энэ ангийг харна».

## Хандалтын үндсэн шалгуурууд

Бүх эрх эдгээрийн аль нэг дээр буцаж очно:

| шалгуур | утга |
|---|---|
| `isMember(user, school)` | `memberships` дотор `ACTIVE` мөр бий |
| `isManagerOf(user, school)` | тэр сургуульд `ACADEMIC_MANAGER` |
| `teachesClass(user, class)` | `class_members` дотор `TEACHER`, `ACTIVE` |
| `studiesIn(user, class)` | `class_members` дотор `STUDENT`, `ACTIVE` |
| `isGuardianOf(parent, student)` | `guardians` дотор `ACTIVE` |
| `guardianSeesClass(parent, class)` | хүүхдийнх нь аль нэг нь тэр ангид сурдаг |

## Хоёр дүртэй хүн

Тэр сургуульд багшилдаг, хүүхэд нь бас тэнд сурдаг хүн:

- `memberships`-д **хоёр мөр** (`TEACHER`, `PARENT`)
- Идэвхтэй дүр нь **сесс дотор** хадгалагдана
- Дүр сэлгэхэд сесс шинэчлэгдэнэ, эрх дахин тооцогдоно
- ⚠️ Багш дүрээрээ байхдаа **өөрийн хүүхдийн** өгөгдлийг багшийн эрхээр
  харж болно (тэр ангийн багш бол). Энэ зөв — давхар эрх нэмэгдэхгүй, зүгээр
  л хоёр эрх зэрэг байна.

## Хаана алдаа гардаг вэ

Энэ гурав нь энэ төрлийн системд хамгийн олон удаа алддаг газар:

1. **`school_id` шүүлт мартагдах.** Нэг `where` дутуу байхад өөр сургуулийн
   өгөгдөл гарна. Шийдэл: бүх асуулга нь сургууль мэддэг давхаргаар дамжина,
   шууд хүснэгт рүү хандахгүй.

2. **Даалгаврын `id`-гаар шууд хандах.** `/homework/<id>` руу өөр ангийн
   сурагч орох. Шийдэл: `id` олдсоны дараа **заавал** холбоосыг шалгана.

3. **Асран хамгаалагчийн холбоос баталгаагүй үүсэх.** Хэн нэгэн өөрийгөө
   хүүхэдтэй холбочихвол бүх хамгаалалт утгагүй болно. Шийдэл: `PENDING`-ээс
   `ACTIVE` болох цорын ганц зам нь багшийн баталгаа.

## Аудит

Дараах үйлдлүүд `audit_log`-д **заавал** бичигдэнэ:

- урилга үүсгэсэн / хүчингүй болгосон
- асран хамгаалагч батлагдсан / татгалзсан
- сурагч ангид нэмэгдсэн / хасагдсан
- багш нэмэгдсэн / хасагдсан
- сурагчийн PIN шинэчлэгдсэн
- нэвтрэх оролдлого олон удаа бүтэлгүйтсэн
